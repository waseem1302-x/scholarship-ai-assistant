# Citation-first assistant architecture

The Phase 6 assistant is an evidence-first decision-support feature. It does
not browse the public internet and it does not treat model output as a source
of truth.

## Retrieval and answer boundary

1. The server searches structured active catalogue fields first.
2. It accepts only a verified source from an approved official source category
   with a recent verification timestamp.
3. It stores an immutable evidence packet containing the query interpretation,
   selected scholarship/source IDs, excerpts, freshness result, and retrieval
   version.
4. The answer engine emits a fixed response schema and attaches every factual
   opportunity claim to a stored `AssistantCitation` pointing to the exact
   catalogue source (and, where present, its immutable excerpt).

Records that are unverified, stale, expired, archived, or conflicting are
rejected from factual answers. If no acceptable evidence remains, the answer
is an abstention—not a guess. Missing dates are labelled as unknown; no
deadline is fabricated.

The included `evidence-template` provider is deterministic and has no API key
or network access. The provider interface is intentionally narrow so a future
server-side provider can be substituted without allowing it to create factual
claims outside the validated evidence packet. Do not send keys, profile data,
application data, or source text to browser code or logs.

## Privacy and retention

Assistant conversations, answers, evidence packets, citations, and feedback
are owned by the requesting user. Every read/write endpoint checks ownership.
Assistant use requires explicit consent before a question is processed. History
may be disabled, which removes retained message text and persists the choice
for future conversations. Students can export or delete all assistant data at
any time. Application documents, notes, reminder text, and other students’ data
are never retrieved by this module.

Default retention is 30 days for retained message history, 365 days for
feedback, and 365 days for citation/audit metadata; these server-only settings
are configurable through `APP_ASSISTANT_*`. Expired content is removed during
assistant operations. No chat, profile, note, document, or reminder content is
written to analytics/logging.

## Operating controls

Assistant configuration uses server-only `APP_ASSISTANT_*` settings:

- provider and model identifiers;
- response and retrieval limits;
- per-user daily/monthly quotas;
- pre-dispatch request limits per authenticated user and IP; and
- source-freshness window.

Provider failures return a persisted safe unavailable outcome and never fall
back to unsupported claims. The provider API key remains server-only; a remote
provider is intentionally unavailable until a reviewed server adapter exists.
Set `APP_ASSISTANT_PROVIDER=evidence-template` for the no-network local mode.
Any future remote adapter must read `APP_ASSISTANT_API_KEY` from a deployment
secret manager, enforce the configured model/version and response limits, map
timeouts to `AssistantProviderUnavailable`, and never receive notes, documents,
or more private data than the user explicitly enabled.

## Citation policy

Each factual sentence generated by the assistant is copied from a structured
catalogue field and receives its own stored `claim_key` and citation. The
citation must point to an officially verified, fresh source belonging to that
same scholarship, with the latest captured source excerpt where available.
Unverified, stale, expired, archived, or conflicting sources cannot support a
factual answer. Recommendations and next actions are labelled separately and
are not represented as official facts.

## Evaluation and incidents

Release checks cover claim-to-source integrity, source freshness and conflicts,
consent/ownership/export/delete, rate limits, provider failures, prompt-
injection source text, and browser accessibility journeys. A suspected
unsupported claim is an incident: disable the provider if necessary, preserve
minimal citation/audit identifiers (not chat content), take the source out of
factual retrieval, correct or remove the answer, and add a regression case
before re-enabling the path.

The release gate is zero cross-user exposures, zero unsupported factual claims
in the approved deterministic evaluation fixtures, and a valid official
citation for every factual scholarship statement. Failed/blocked/abstained
answers must contain no factual citations. Run the backend suite, lint, frontend
component tests, production build, and the configured browser journey suite on
every release candidate; record provider latency and per-request cost outside
the assistant content store.

## User-facing disclaimer

> The assistant helps organize and explain source-backed scholarship
> information. Always confirm requirements, deadlines, funding, and eligibility
> directly with the official provider before applying. The assistant cannot
> guarantee eligibility, funding, admission, or visa outcomes.
